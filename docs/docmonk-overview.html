Local-first knowledge engine

Ask your documents and your code anything.
Get answers with exact sources.

DocMonk indexes folders of documents and repositories on your machine (or on your own OpenSearch / Elasticsearch) and answers with the file, page, heading or line every fact came from.

📄 Documents

PDF, Word, PowerPoint, spreadsheets, HTML, Markdown, e-mail, OCR for scans. Headings, tables and pages preserved.

💻 Code

Symbols, callers, callees, HTTP routes and impact analysis across many languages.

🔗 Linked

Specs and docs are linked automatically to the code they mention.

🔒 Private

No telemetry, no cloud. External AI only if you explicitly opt in.

Get going in 5 minutes

Install, add folders, index, ask

# macOS / Linux
curl -fsSL https://raw.githubusercontent.com/gzarog/DocMonk/main/install.sh | sh

docmonk init                               # create ~/.docmonk
docmonk source add ~/company-docs          # register folders
docmonk source add ~/code/payments
docmonk index                              # index, then build relationships
docmonk status                             # progress, problems, errors
docmonk explore "what breaks if SettlementService changes?"

Keep it fresh with docmonk daemon start: changed files are re-indexed in the background.

How a run works

Index everything first. Relationships after a barrier.

  • A graph failure never delays or rolls back a published index; it is reported separately as a partial success.
  • The daemon follows the same barrier: graph work runs only when no index pass is queued or running.
Consistency

Every graph belongs to one exact published index

Versioned, atomic

A graph records the base build and generation it was derived from. Local mode promotes it in one SQLite transaction; server mode writes an invisible generation and promotes it with one compare-and-swap fenced by the writer lease and the expected base build.

Never mixed

Before deriving edges, each code file is re-read and checked against the hash the index published. If a file changed mid-run the graph becomes stale and nothing is published, until the next index pass.

Readers stay honest

Callers, callees, impact and links only return a graph that matches the active index. Otherwise they return nothing, and status says why.

Doing only the work that changed

Incremental by file and by symbol

StepWhat is redone
ParseOnly files whose content hash or index write changed.
ResolveThe changed files, plus unchanged files with a reference to a symbol (qualified or bare name) whose definitions were added, removed, moved or became ambiguous. Candidates are looked up per symbol; only changed outcomes are written.
LinkChanged code and documents are relinked; manual links are re-applied.
Server publishUnchanged files' edges and links are copied forward on the cluster into the new generation (no duplicates, no client round trip); only changed files are bulk-written.
FallbackMissing dependency data triggers a full graph recomputation, still without reindexing any content.

Tests check that an incremental graph is identical to a full recomputation of the same index.

  • index_state says whether the source is searchable; relationship_state says whether its graph is current. They never hide each other.
  • Run phases are explicit: indexing → indexed → relationships → done.
  • The same report backs the CLI, --json, the Admin UI and the MCP docmonk_status tool, in local and server mode.
Settings

A few switches that matter

SettingDefaultEffect
indexing.relationships_enabledtrueBuild relationship graphs after indexing. Off: no graph jobs, graphs hidden (not deleted), no reindex when toggled.
indexing.max_parallel_sourcesautoSources indexed (and graphs built) at the same time.
documents.pdf_modeaccuratefast reads only the PDF text layer.
search.semanticfalseLocal embedding-based semantic search.
storage.modelocalserver uses OpenSearch / Elasticsearch as the authoritative store.

Change any value with docmonk config set KEY VALUE.

Large or shared corpora

OpenSearch / Elasticsearch as the source of truth

Atomic publication

Builds publish by compare-and-swap; a failed rebuild keeps serving the previous index.

Writer leases

One host writes a source at a time; fencing tokens stop superseded hosts from publishing.

Copy-forward

Unchanged files, and now unchanged graph records, gain the new build id in place on the cluster.

Credentials

Only from environment variables, never written to config.yaml.

When something looks off

Troubleshooting

SymptomWhat to do
Relationships stale or failedThe index is fine. Run docmonk index again (stale) or docmonk relationships build; see the reason in status --verbose.
A folder is offlineIts knowledge is kept. Reconnect it and run docmonk index.
Files failed / retryingdocmonk status --errors. Temporary failures retry automatically.
Lock held by another processWait or docmonk daemon stop. Never delete the lock file.
Anything elsedocmonk doctor, then docmonk rebuild --fresh if the index is damaged.
